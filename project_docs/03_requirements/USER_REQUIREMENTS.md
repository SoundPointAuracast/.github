# USER_REQUIREMENTS

Статус документа: DRAFT. Категории: FACT / ASSUMPTION / HYPOTHESIS / TARGET.

## Основной сценарий: студент на лекции

Преподаватель говорит в микрофон. Студент в аудитории хочет получить
речь с максимальным качеством и с текстовой поддержкой.

## Варианты получения

### Вариант A — Auracast напрямую
Студент принимает Auracast-поток на совместимое устройство
(наушники / смартфон / слуховой аппарат с LE Audio).
- Статус: TARGET. Совместимость конкретных устройств не подтверждена.

### Вариант B — Bridge-T
Аудио: Auracast → Bridge-T → индукционная катушка → T/MT режим
слухового аппарата или КИ.
- Статус: HYPOTHESIS / TARGET. Требует проверки.

### Вариант C — Route+ App (текст)
Студент использует приложение для транскрипта, заметок, «Не расслышал».
- Статус: TARGET.

### Вариант D — звук + текст одновременно
Студент получает Auracast-аудио и синхронизированный текст.
- Статус: HYPOTHESIS. Ключевая архитектурная гипотеза проекта.

## Ситуации, которые обязательно рассмотреть

| Ситуация | Потребность пользователя |
|---|---|
| Дальний ряд | Прямой сигнал вместо акустики зала |
| Шум | Чистый фид вместо микрофона смартфона |
| Реверберация | Разборчивость без «эха» |
| Потерянная фраза | «Не расслышал»: повтор / подсветка |
| Незнакомый термин | Быстрый доступ к тексту/определению |
| Иностранная речь | Перевод (PHASE 2) |
| Не хочет прерывать преподавателя | Бесшумный индивидуальный доступ к тексту |

## Требования (черновые)

- UR-01 (TARGET): вход в лекцию без сложной настройки (QR/код).
- UR-02 (TARGET): получение аудио с малой задержкой.
- UR-03 (TARGET): синхронизированный текст.
- UR-04 (TARGET): возможность отметить непонятный фрагмент без
  прерывания лекции.
- UR-05 (TARGET): индивидуальные настройки доступности.
- UR-06 (TARGET): работа на типовом смартфоне пользователя.
- UR-07 (ASSUMPTION): в аудитории есть стабильная сеть для текстового слоя.
- UR-08 (HYPOTHESIS): текст от чистого фида точнее, чем от микрофона смартфона.
