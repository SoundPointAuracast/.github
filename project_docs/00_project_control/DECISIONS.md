### D-002 — 2026-09-26 — Разделять категории утверждений

- **Решение:** каждое утверждение маркируется FACT / SOURCE /
  ENGINEERING ASSUMPTION / HYPOTHESIS / TARGET / MEASURED RESULT.
- **Обоснование:** TARGET нельзя выдавать за измеренную характеристику.
- **Статус:** ACCEPTED.

### D-003 — 2026-09-26 — Не заявлять мировую новизну

- **Решение:** до патентного поиска (GATE 7) не делать заявлений
  о глобальной новизне. Архитектура «один источник → аудио + текст» —
  это HYPOTHESIS, а не новизна.
- **Обоснование:** требуется prior art.
- **Статус:** ACCEPTED.

### D-012 — 2026-09-26 (GATE 2) — ASR питается от PCM до LC3

- **Решение:** в архитектуре ASR получает отдельную ветку чистого PCM
  (электрический split), а не декодированный LC3-поток.
- **Обоснование:** независимость от кодека, максимальное качество для ASR;
  см. `SYSTEM_ARCHITECTURE.md`, `DATA_PIPELINE.md`.
- **Статус:** ACCEPTED (ARCHITECTURE).

### D-013 — 2026-09-26 (GATE 2) — Baseline LC3 = 24_2_1

- **Решение:** базовая конфигурация — 24_2_1 (HA-HQ, обязательна для sink),
  с обязательной поддержкой 16_2_1.
- **Обоснование:** SIG рекомендует 24_2_1 при слышимом ambient (меньше эха
  при смешении с живым звуком); см. `LC3_CONFIGURATION_MATRIX.md`.
- **Статус:** ACCEPTED (уточняется экспериментом E04).

### D-014 — 2026-09-26 (GATE 2) — Latency target: ≤60 мс (допустимо ≤100 мс)

- **Решение:** целевая сквозная задержка ≤60 мс; допустимая ≤100 мс;
  >150 мс — брак. Легаси ≤300 мс отвергнута как цель.
- **Обоснование:** смешение с живым звуком → эхо/гребенчатые эффекты;
  см. `LATENCY_DEEP_DIVE.md`.
- **Статус:** ACCEPTED (TARGET; проверяется E01).

### D-015 — 2026-09-26 (GATE 2) — App не реализует Auracast stack

- **Решение:** Route+ App не обещает собственное Auracast-подключение;

- **Обоснование:** Android SystemApi + BLUETOOTH_PRIVILEGED; iOS без
  LE Audio; см. `MOBILE_AURACAST_SUPPORT.md`.
- **Статус:** ACCEPTED.
