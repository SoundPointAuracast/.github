# AI_WORKFLOW

Три режима работы ИИ-ассистентов в проекте.
Режим выбирается по типу задачи, а не по сложности формулировки.

---

## DeepSeek V4.1 Flash — LOW

**Для чего:**

- mkdir;
- mv / cp;
- переименование;
- Git status;
- форматирование;
- простая навигация;
- механические изменения.

**Правила:** не принимает инженерных решений, не меняет смысл документов.

---

## DeepSeek V4.1 Flash — HIGH

**Для чего:**

- обычный инженерный анализ;
- анализ документов;
- разработка приложения;
- backend / frontend;
- тесты;
- архитектурные документы;
- BOM;
- UX;
- подготовка отчётов.

**Правила:** опирается на `SOURCE_OF_TRUTH.md`; помечает допущения
как ASSUMPTION / HYPOTHESIS / TARGET.

---

## DeepSeek V4.1 Flash — MAX

**Только для сложных задач:**

- Bluetooth Core / LE Audio;
- BAP;
- PBP;
- BASS;
- BIS / BIG;
- LC3;
- latency;
- Android / iOS Auracast support;
- системная архитектура;
- конкуренты;
- deep research;
- patent prior art;
- патентоспособность;
- новизна;
- roaming;
- confidence-aware algorithms;
- сложная экономика;
- критический аудит.

**Правила:** каждое утверждение сопровождается категорией (FACT / SOURCE /
ASSUMPTION / HYPOTHESIS / TARGET / MEASURED). Никаких заявлений о мировой
новизне без патентного поиска. См. `09_novelty_rid/`.

---

## Общие правила для всех режимов

1. Не менять исходники презентаций и заявок.
2. Не выдавать TARGET за MEASURED RESULT.
3. Не делать патентных заявлений на ранних этапах.
4. Не создавать вложенный корень проекта.
5. Не выполнять `git commit` без явного указания.
6. Фиксировать изменения в `CHANGELOG.md`.

---

## Маршрутизация задач (сводка)

| Задача | Режим |
|---|---|
| Создать папку, переместить файл | LOW |
| Написать раздел требований, отчёт | HIGH |
| Разобрать BAP/PBP/BASS, LC3, prior art | MAX |
| Простой рефакторинг структуры | LOW |
| UX приложения, BOM | HIGH |
| Аудит новизны, роуминга, confidence | MAX |
