# LATENCY_TEST_PROTOCOL

Эксперимент E01. Дата плана: 2026-09-26. Статус: PROTOCOL (не выполнен).

## Цель

Измерить реальную **end-to-end** задержку «акустический вход → акустический
выход приёмника» для стенда Auracast и, отдельно, вклад каждого звена.
Проверить применимость baseline 24_2_1.

## Гипотеза

H-L1: end-to-end задержка стенда ≤ 100 мс, при выборе low-latency QoS —
≤ 60 мс (категория TARGET, см. `02_research/02_lc3_latency/LATENCY_DEEP_DIVE.md`).

## Независимые переменные

- QoS/конфигурация: 16_2_1, 16_2_2, 24_2_1, 24_2_2 (минимум 4 условия).
- Presentation delay, если управляем: 20 / 30 / 40 мс.
- Приёмник: devkit sink; опционально consumer-приёмник (AuraClip и т. п.).
- Условия эфира: тихая аудитория; зашумлённая; с препятствиями.

## Зависимые переменные

- End-to-end latency (мс): медиана, p95, разброс (минимум 100 измерений).
- Разложение: encode, transport (оценка), presentation, decode, DAC (если
  измеримо).
- Джиттер и потери.

## Оборудование

- Источник: ПК/генератор → nRF5340 Audio DK (Broadcast Source) либо
  FMA120/MoerLink.
- Приёмник: nRF5340 Audio DK (Broadcast Sink) с аналоговым выходом;
  опционально Avantree AuraClip (3.5 мм).
- Осциллограф / звуковая карта с временны́м разрешением ≥1 мс.
- Акустика: громкоговоритель + измерительный микрофон ИЛИ электрическая
  петля (прямое электрическое измерение источника и выхода).

## Метод (базовый)

1. Собрать стенд: источник → Auracast → приёмник → аналоговый выход.
2. Подать импульс/чирп с известной меткой времени (короткий burst с
   синхросигналом).
3. Записать одновременно: (а) входной электрический сигнал источника,
   (б) выходной аналоговый сигнал приёмника.
4. Определить задержку кросс-корреляцией с суб-мс точностью.
5. Повторить ≥100 раз на каждую конфигурацию; сменить условия.
6. Отдельно зафиксировать заявленный presentation delay и QoS (из конфигурации).

## Метод (акустический контроль)

Для проверки «микрофон → ухо»: громкоговоритель → измерительный микрофон
источника → Auracast → приёмник → громкоговоритель/эмулятор уха → микрофон.
Учитывать задержки измерительной акустики.

## Метрики

- latency_mean, latency_median, latency_p95, latency_max.
- jitter (std dev).
- packet loss / retransmission count (если доступно).
- Разложение по звеньям.

## Критерии приемлемости

| Критерий | Значение |
|---|---|
| Target | ≤ 60 мс |
| Acceptable | ≤ 100 мс |
| Reject | > 150 мс |

## Ожидаемый результат

- Таблица latency по конфигурациям и условиям.
- Понимание, какой компонент доминирует.
- Рекомендация baseline QoS/конфигурации для MVP.

## Ограничения

- Задержка чужого слухового аппарата не контролируется; для стенда
  измеряем электрический/аналоговый выход.
- Акустические измерения включают задержку помещения.
