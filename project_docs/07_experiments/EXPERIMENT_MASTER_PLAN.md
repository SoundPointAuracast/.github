## E01 — Audio latency
- **RQ:** какова реальная end-to-end задержка «микрофон → аналоговый выход»?
- **H:** ≤100 мс на 24_2_1; ≤60 мс при low-latency QoS.
- **IV:** QoS (16_2_1/16_2_2/24_2_1/24_2_2), presentation delay (20/30/40).
- **DV:** latency (mean/median/p95), jitter, потери.
- **Оборудование:** nRF5340 DK ×2, звуковая карта/осциллограф.
- **Метод:** импульс/чирп → кросс-корреляция; ≥100 повторов.
- **Acceptance:** target ≤60, acceptable ≤100, reject >150 мс.
- **Выход:** таблица latency + доминирующее звено.
- Протокол: `07_experiments/latency/LATENCY_TEST_PROTOCOL.md`.

## E02 — RF coverage
- **RQ:** какое покрытие даёт один узел в типовой аудитории?
- **H:** стабильное покрытие всей аудитории одним узлом при
  соответствующем размещении.
- **IV:** позиция TX, мощность, препятствия, число людей.
- **DV:** RSSI/потери, зоны отказа, BER/FER.
- **Оборудование:** TX + переносимый RX + телефон/логгер.
- **Метод:** сетка точек, измерения в каждой.
- **Acceptance:** нет зон без приёма в посадочной зоне.
- **Выход:** карта покрытия; число узлов для зала.

## E03 — Packet stability
- **RQ:** устойчивость потока во времени и при движении людей.
- **H:** потери ниже порога, заметного на слух, на базовой конфигурации.
- **IV:** QoS, дистанция, загруженность эфира (Wi-Fi/др. BT).
- **DV:** потери/переповторы, разрывы, глитчи.
- **Оборудование:** стенд E01.
- **Метод:** длительная запись (≥1 ч) с логом.
- **Acceptance:** отсутствие разрывов в сценарии лекции.
- **Выход:** протокол устойчивости.

## E04 — LC3 configuration comparison
- **RQ:** какая конфигурация оптимальна для речи в аудитории?
- **H:** 24_2_1 — лучший баланс качества/задержки/совместимости.
- **IV:** 16_2_1, 16_2_2, 24_2_1, 24_2_2, 48_2 (если доступно).
- **DV:** субъективная разборчивость (MOS/разборчивость), latency,
  совместимость приёмников, airtime.
- **Оборудование:** стенд + панель слушателей.
- **Метод:** слепое сравнение одних фрагментов.
- **Acceptance:** конфигурация проходит и технически, и субъективно.
- **Выход:** обоснование baseline.

## E05 — Clean-feed vs smartphone ASR
- **RQ:** насколько WER(CLEAN FEED) лучше WER(телефон) в аудитории?
- **H (H1):** FEED устойчиво лучше, разрыв растёт с дистанцией/реверберацией.
- **IV:** FEED / PHONE_NEAR / PHONE_MID / PHONE_BACK; условия зала.
- **DV:** WER, CER, timestamp precision, hallucinations.
- **Оборудование:** синхронная запись, ≥2 телефона, RIR.
- **Метод:** одновременная запись; ground truth; 1–2 ASR-модели.
- **Acceptance:** измеримый выигрыш FEED; иначе — пересмотр гипотезы.
- **Выход:** таблицы + решение о clean-feed ASR.
- Протокол: `07_experiments/asr_accuracy/ASR_COMPARISON_PROTOCOL.md`.

## E06 — Caption latency & sync
- **RQ:** какова задержка partial/final и точность таймкодов?
- **H:** partial ≤1 с; final ≤3 с; timestamp precision ≥60% @200 мс.
- **IV:** ASR-движок, длина сегмента, окно N.
- **DV:** caption latency, word timestamp error, стабильность текста.
- **Оборудование:** ASR-стенд + эталонная разметка.
- **Метод:** разметка вручную подвыборки; сравнение.
- **Acceptance:** «Не расслышал» показывает корректный фрагмент.
- **Выход:** параметры для Route+.

## E07 — Bridge-T audio transfer
- **RQ:** работает ли связка Auracast sink → индукция → T/MT?
- **H:** измеримый сигнал в T-режиме; эхо не мешает.
- **IV:** выходной уровень, расстояние до СА, катушка (neckloop vs старая),
  экранирование.
- **DV:** уровень сигнала в СА (субъективно/через телеметрию), разборчивость,
  гул.
- **Оборудование:** AuraClip/DK + neckloop + СА с T.
- **Метод:** серия прослушиваний + измерения поля (если есть прибор).
- **Acceptance:** стабильный разборчивый сигнал без гула.
- **Выход:** протокол E07 + решение по катушке.
- См. `13_demo/hardware_demo/BRIDGE_T_MVP_SPEC.md`.
